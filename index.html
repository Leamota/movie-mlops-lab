🎬 Catching Data Drift in Movie Recommendations with Evidently AI

How lightweight monitoring reveals shifting user tastes and keeps recommendations relevant.

Introduction

Streaming platforms rely on recommendation systems to keep users engaged. These models learn from past viewing behavior, but preferences change quickly—what worked last month may fail today. This mismatch is called data drift, and it can silently reduce model accuracy and user satisfaction.

Monitoring drift is a core part of MLOps. Without it, models degrade unnoticed, leading to irrelevant suggestions and higher churn. In this post, I show how Evidently AI, an open-source tool, can detect drift in a simulated streaming scenario and provide actionable insights for retraining.

Problem addressed

The challenge is data drift: when user behavior evolves, the recommendation model no longer reflects current preferences. For streaming platforms, this means irrelevant suggestions, lower engagement, and potential churn. Monitoring drift ensures models remain aligned with reality.

Practical use in movie-streaming scenario

I simulated a streaming environment where user logs capture region, device, age group, and genre preferences. A baseline model predicted watch probability from these features and produced reference predictions on historical logs.

To emulate changing tastes, I shifted the genre distribution—specifically, a surge in interest for animated shows—creating a current dataset. Evidently AI compared the reference and current datasets and flagged drift in genre features and prediction scores.

In a real platform, this setup enables engineers to detect misalignment early, trigger retraining when drift exceeds thresholds, and keep recommendations relevant as trends evolve.

Baseline model results

The watch-probability model predicts whether a user is likely to watch a title based on region, device, age group, and genre affinities.

While imperfect, these scores show the model is learning meaningful patterns—enough to demonstrate the importance of drift monitoring.

Simulating drift

To simulate real-world change, I introduced an increase in interest for animated shows. Comparing the “current” dataset to the “reference,” users became more inclined toward animation.

In production, shifts in content trends or demographics can quickly diminish the relevance of yesterday’s model.

Monitoring with Evidently

I used Evidently’s DataDriftPreset to compare reference vs. current data and generate an HTML dashboard. 

from evidently import Report
from evidently.metric_preset import DataDriftPreset

report = Report(metrics=[DataDriftPreset()])
report.run(reference_data=ref_logs, current_data=cur_logs)
report.save_html("data_drift_report.html")

Opening the dashboard revealed clear changes:

  • Feature drift: genre_anime and aff_anime distributions shifted significantly.
  • Prediction drift: The model’s score distribution changed, indicating potential calibration issues.
  • Target drift: Watch outcomes differed between reference and current periods.

Analysis

The experiment with Evidently AI involved several layers of analysis:

  • Diagnostic analysis: Identifying drift across features and predictions.
  • Comparative analysis: Observing shifts in genre preferences and affinities.
  • Performance analysis: Understanding baseline ROC-AUC and PR-AUC before drift.
  • Operational analysis: Designing realistic drift thresholds for production alerts.

Together, these analyses show not only that drift exists, but also how it impacts model reliability and what actions teams can take to maintain relevance.

Strengths, limitations, and lessons learned

Working with Evidently AI revealed both advantages and areas for improvement:

  • Strengths:
    • Easy Python integration and interpretable HTML reports.
    • Holistic view: feature, prediction, and target drift.
    • Clear visuals useful for both engineers and stakeholders.
  • Limitations:
    • Primarily diagnostic—does not prescribe retraining strategies.
    • Static dashboards unless hooked to real monitoring pipelines.
    • Large-scale data may require sampling or distributed processing.
  • Lessons learned:
    • Model degradation happens silently without monitoring.
    • Best results come when drift detection triggers automated retraining.
    • Setting thresholds (e.g., drift_share > 0.3) helps define actions.

Conclusion

Continuous monitoring is essential for production ML systems. A movie streaming platform that catches drift early will deliver more relevant recommendations, sustain user engagement, and build trust.

This experiment demonstrates how Evidently AI can act as a lightweight guardrail for recommendation systems—detecting drift, signaling retraining needs, and helping teams stay aligned with evolving user tastes.
