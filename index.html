🎬 Catching Data Drift in Movie Recommendations with Evidently AI

How lightweight monitoring reveals shifting user tastes and keeps recommendations relevant.

Introduction

Recommendation systems in movie streaming services rely heavily on user behavior to suggest films. But user tastes change rapidly—thrillers may dominate one month, while animated shows surge the next. Without adaptation, machine learning models can quickly become outdated and irrelevant.

Data drift refers to statistical changes in input data over time. It occurs when incoming data no longer aligns with the data the model was trained on, leading to degraded performance.

In this post, I demonstrate how this challenge can be addressed using Evidently AI, an open‑source monitoring tool, to detect drift in a simulated movie‑streaming scenario.

Problem addressed

The core challenge is data drift: when user behavior evolves, the recommendation model no longer reflects current preferences. For streaming platforms, this means irrelevant suggestions, lower engagement, and potential churn. Monitoring drift ensures models remain aligned with reality.

Baseline model results

To predict user behavior, I built a simple watch‑probability model. It predicts whether a user is likely to watch a movie based on region, device, age group, and genre affinities.

Baseline performance:

ROC‑AUC: 0.705 PR‑AUC: 0.562

While imperfect, these scores show the model is learning meaningful patterns—enough to demonstrate the importance of drift monitoring.

Simulating drift

To simulate real‑world change, I introduced an increase in interest for animated shows. Comparing the “current” dataset to the “reference,” users became more inclined toward animation.

In production, shifts in content trends or demographics can quickly diminish the relevance of yesterday’s model.

Monitoring with Evidently

I used Evidently’s DataDriftPreset to compare reference vs. current data and generate an HTML dashboard. 

from evidently import Report
from evidently.metric_preset import DataDriftPreset

report = Report(metrics=[DataDriftPreset()])
report.run(reference_data=ref_logs, current_data=cur_logs)
report.save_html("data_drift_report.html")

Opening the dashboard revealed clear changes:

  • Feature drift: genre_anime and aff_anime distributions shifted significantly.
  • Prediction drift: The model’s score distribution changed, indicating calibration issues.
  • Target drift: Watch outcomes differed between reference and current periods.

Insights and takeaways

  • Models degrade silently: Without monitoring, recommendations can become irrelevant without obvious failures.
  • Evidently surfaces instability: The dashboard highlights which features are drifting, guiding retraining decisions.
  • Operational workflow: In production, thresholds (e.g., drift share > 0.3) can trigger alerts or automated retraining.
# Programmatic summary example
summary = report.as_dict()
drifted = summary["metrics"][0]["result"]["data_drift"]["dataset_drift"]
drift_share = summary["metrics"][0]["result"]["data_drift"]["drift_share"]
print(f"Dataset drift: {drifted}, drift share: {drift_share:.2f}")

Conclusion

Continuous monitoring is essential for production ML systems. A movie streaming platform that catches drift early will deliver more relevant recommendations, sustain user engagement, and build trust.

This experiment demonstrates how Evidently AI can serve as a lightweight, accessible guardrail for recommendation systems—helping teams detect drift, plan retraining, and keep models aligned with evolving user tastes.
